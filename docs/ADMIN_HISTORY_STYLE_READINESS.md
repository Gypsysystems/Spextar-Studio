- **D1:** explicit Project Admin publishes; Author/Reviewer/Viewer do not publish by those roles. A Project Admin who approved may publish; no first-scope separation of duty.
- **D2:** one complete document per release; internal authenticated read-only inspection; default variables and neutral conditions. No external portal, PDF, Word or filtered output.
- **D3:** retained immutable releases; block destructive parent deletion that would destroy them. Current authorized project access governs release reads, including frozen captured dependencies.

These decisions are carried forward, not reopened. Publishing remains unimplemented and requires accepted #9 plus a server-verified immutable approval package containing the necessary dependency/context closure. Draft → In Review → Approved → Published and Changes Requested → Draft remain authoritative; editing approved content creates a new Draft, and publishing creates a Release.

## Recommended minimal scope and state requirements

**Project Settings:** keep existing explicit-save/member/status design. Validate and close G1 and concrete accessibility/state defects before adding settings. No new preferences, project ownership model, import/export or broad refactor. Check metadata and role conflicts independently; preserve edits on failures and prevent automatic write retry. Reconcile ambiguous post-write confirmation via reload. Keep empty candidates distinct from failed candidate reads; do not show inaccessible raw UUIDs.

**Workspace/Organization Settings and Administration:** retain existing contextual management dialogs. Explain owner-only organization deletion, no organization archive and archive-first workspace/project deletion. Confirm how beta colleagues obtain authorized parent membership before promising self-service administration. If parent-member management is approved, add typed scoped Services with server enforcement, fresh expected-role checks and explicit owner/last-admin policies; no privileged browser Auth API, email directory, guessed RPC, direct-insert fallback or new global Admin console.

**History:** keep its placeholder during #9 and Publishing. Small first evidence UI belongs to Review; release history belongs to Publish. A later History read composition can reference accepted immutable domain records with explicit kinds and pagination, but cannot become another lifecycle/audit engine. Revision storage/diff/restore are separate optional work.

**Style Guide:** retain honest placeholder for beta. If product wants a useful first increment, recommend a **read-only project writing-standards page**: short terminology entries (preferred term, discouraged term, human rationale) plus concise writing guidance. Reads for authorized project readers; proposed edits by explicit Project Admin only. This recommendation requires a real approved storage/service/version/conflict contract and product choice; no synthetic backend examples, free-form executable rules, AI, automatic replacement, block-on-save/approve/publish, shared inheritance or reusable style presets. Existing reusable snippets solve content reuse, not style-rule governance. Until accepted, no new schema or capability is authorized. Read-only standards are lower scope than enforcement because no evaluator, false-positive handling or authoring interception is needed.

**Brand Outputs:** retain placeholder; link/explain accepted Publish availability in a later approved copy task. First-scope releases use existing renderer and approved product presentation. Customer brand profiles/templates, uploads, PDF/Word generation, external portal, filtered output and rollback are excluded. If versioned styles ever affect output, freeze their identity/content with the approved package before review; never apply today's mutable template to an old release.

Every future real surface must distinguish loading, genuine empty, missing/denied, malformed/unsupported, network/error/retry and access loss. Writes additionally need validation, pending/disabled reason, confirmation/cancel, success, stale/conflict, uncertain outcome and explicit reload preserving local work. Read-only pages must issue zero writes; unavailable schema fails closed without demo data. No conflict state is necessary on the current no-data placeholders; generic project-scope loading/error/denial still applies.

For affected Settings, lifecycle dialogs, future evidence/standards screens, require keyboard-only operation, labels/error associations, status announcements, focus trap/return/Escape, visible focus, meaningful headings/lists, safe disabled explanations without hover, touch targets and no horizontal overflow. Exercise desktop/mobile and dark/light with long names and missing identity labels. Reuse ProjectScope, PageHeader, ErrorState/EmptyState/Skeleton, Button, Input/Textarea, Dialog/AlertDialog, StatusPill, identity helpers and semantic background/foreground/border/primary/destructive/focus tokens. Preserve local Inter, #6236FF, 240px/72px responsive navigation and approved Signature X/purple-dot brand components. No new visual pattern is needed; no UI change or Figma-fidelity claim is made here.
