## Accepted design versus in-progress work

[PR #11 product-owner acceptance](https://github.com/Gypsysystems/Spextar-Studio/pull/11#issuecomment-6499719689) is explicit:

- D1: only explicit Project Admin publishes; an Admin who approved may publish in the first scope. Author/Reviewer/Viewer and inherited organization/workspace administration have no implied publisher authority.
- D2: one complete document, internal authenticated read-only inspection, default variables and neutral conditions; no portal/PDF/Word or condition-filtered output.
- D3: retained immutable release history; destructive parent deletion must block when it would destroy releases. Current authorized project access governs historical reads, including the captured dependency closure.

These decisions are accepted baseline, not recommendations to reopen. Merged design-file language still calls them pending; acceptance supersedes that wording. No implementation exists from design acceptance alone.

Issue #9 supplies the planned document submission, immutable outline/body snapshot, Reviewer/Admin decisions, Changes Requested → Draft, In Review/Approved write locks and explicit new Draft. It is not evidence those behaviors already work. Publishing must reconcile accepted #9 and freeze the full transitive variable/condition/reusable dependency/context package reviewed by approvers. If #9 freezes only bodies, the accepted Publishing design already covers the required approval-package extension; do not create a parallel lifecycle or resolve mutable dependencies at publish time.
