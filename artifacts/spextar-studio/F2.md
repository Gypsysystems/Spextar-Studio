# F2 Documents and Topics

## Runtime contract

Backend mode reads `public.documents` scoped by `project_id`, then `public.topics`
scoped by those document IDs. Pagination prevents default PostgREST page limits
from silently truncating outlines or counts. The ordered view is a preorder
traversal of `parent_topic_id`, sorting siblings by `sort_order` then ID.
Missing parents, duplicate IDs, cross-document parents and cycles fail explicitly.

Database `in_review` maps to UI `in-review`; published is also supported.
`settings.kind` carries the UI's concept/task/reference metadata.
`settings.type` and `settings.version`, when present, supply document presentation
metadata. Missing presentation metadata defaults to guide/unversioned; no invented
database columns or authoring storage are used.

Only explicit project admin/author memberships enable mutation controls and the
adapter's additional guards. Organization/workspace administration alone never
upgrades a reviewer/viewer into a content author. Supabase permissions/RLS remain
authoritative on every actual request.

The existing `create_document`, `create_topic`, `move_topic`, `promote_topic`,
`demote_topic`, `duplicate_document` and `duplicate_topic_subtree` RPCs perform
structural writes. Authenticated GET probes resolve their SQL parameter names;
missing or incompatible signatures fail closed before a write. Writes are never
retried with speculative argument names or replaced by client-side tree copies.

## Metadata autosave versus body drafts

- Title/slug/status/description/settings updates write only whitelisted columns.
- Topic kind is metadata in JSON settings, not a body representation.
- Metadata saves are debounced and serialized, with pending/saving/saved/error
  states and explicit retry after failure.
- Successful writes invalidate document detail/list and project detail/list
  caches, including counts, pickers and breadcrumbs.
- Body paragraphs never enter a write payload. Body/content settings keys are
  rejected rather than used as an alternate authoring store.
- Local body drafts survive metadata/tree refreshes in the same open Author
  workspace. Discard body edits does not undo metadata already saved.
- Body drafts are lost on document/page session exit or reload; a visible banner
  and unload warning communicate this. Persisting bodies is reserved for F3.
- Demo fixtures and preview editing remain local. Backend persistence actions
  are not silently implemented through demo storage.

## Validation limits

injected Supabase doubles. They are not proof of authenticated live RLS/RPC
execution. This workspace has no authorized test account or administrative schema
connection; do not grant anonymous access or request server keys for the browser.
